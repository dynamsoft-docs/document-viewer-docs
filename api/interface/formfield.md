# FormField

The raw data type of a form field. It is returned by [`FormManager.getFields()`]({{ site.api }}class/formmanager.html#getfields) and [`FormManager.getFieldByUid()`]({{ site.api }}class/formmanager.html#getfieldbyuid), and is also used as the `newFieldProps` of the [`FormFieldModifiedEvent`]({{ site.api }}interface/formfieldmodifiedevent.html). It is a serializable snapshot; the properties may vary depending on the field type, the parser version, or extended fields.

## Syntax

```typescript
interface FormField {
  uid?: string;
  alternateName: string;
  name?: string;
  type?: string;
  value?: string | number | boolean | null | string[];
  readonly?: boolean;
  visible?: boolean;
  required?: boolean;
  removeUponSaving?: boolean;
  rawFieldData?: any;
}
```

## Attributes

### uid

The globally unique uid of the field, generated by DDV when parsing the form. It is unique within the current DDV runtime.

### alternateName

The alternate name of the field, which can be used for accessibility or tooltips.

### name

The name of the field.

### type

The type of the field.

### value

The current value of the field. The concrete value type depends on the field type: a text field usually uses `string`, a check box usually uses `boolean`, and a list box may use `string[]`. `null` means the field currently has no value.

### readonly

Whether the field is read-only for direct user editing.

### visible

Whether the field and its associated controls are displayed.

### required

Whether the field is required to have a valid value.

### removeUponSaving

Indicates whether the field should be removed when the PDF is saved. If set to `true`, the field is removed upon saving. For example, a signature can be applied over the field, and the field can then be removed from the PDF.

### rawFieldData

The raw field data kept by the parser. It is not a fixed structure and may vary depending on the PDF type or the parser version. Business code must perform its own type checks when reading it.

## Remark

- All the properties except `alternateName` are optional; callers must be able to handle missing properties caused by different field types.
