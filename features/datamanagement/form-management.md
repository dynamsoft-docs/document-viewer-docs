# Form Management

DDV provides PDF form field management and form-filling functionality through the [`FormManager`]({{ site.api }}class/formmanager.html) class. With `DDV.formManager`, you can read the raw data of the form fields in a document and update their runtime properties (value, visibility, read-only, required, etc.). Combined with the form-related methods and events of [`EditViewer`]({{ site.api }}class/editviewer.html), you can also locate the rendered form widgets in the viewer and respond to widget clicks.

The form functionality is provided by the standalone form [plugin](/features/plugins-and-on-demand-loading.md), which must be installed after the annotation plugin.

## Get the raw data of form fields

### Get all the fields in a document

Use [`getFieldRaws()`]({{ site.api }}class/formmanager.html#getfieldraws) to get the raw data snapshots of all the form fields in the specified document. Each snapshot merges the field definition with the current form runtime state.

```typescript
const docUid = editViewer.currentDocument.uid;
const raws = Dynamsoft.DDV.formManager.getFieldRaws(docUid);

raws.forEach(raw => {
  console.log(raw.uid, raw.type, raw.value);
});
```

### Get a field by its uid

Each field has a globally unique field uid, which is generated by DDV when the form is parsed. Use [`getFieldRawByUid()`]({{ site.api }}class/formmanager.html#getfieldrawbyuid) to get a single field snapshot.

```typescript
const field = Dynamsoft.DDV.formManager.getFieldRawByUid(fieldUid);
if (field) {
  console.log("Current field value:", field.value);
}
```

The returned object is a [`PdfFormFieldRaw`]({{ site.api }}interface/pdfformfieldraw.html). All the properties are optional and may vary depending on the field type, so you must handle missing properties in your business code. For example, a text field usually has a `string` value while a check box usually has a `boolean` value. The `value` type is [`PdfFieldValue`]({{ site.api }}enumeration-type/pdffieldvalue.html).

## Update the runtime properties of a field

Use [`setFieldProps()`]({{ site.api }}class/formmanager.html#setfieldprops) to update the runtime properties of a field. Only the properties passed in are updated; the others stay unchanged. The associated form controls refresh automatically.

For example, fill in a text field and mark it as read-only:

```typescript
Dynamsoft.DDV.formManager.setFieldProps(fieldUid, {
  value: "Filled",
  readonly: true,
});
```

Check a check box:

```typescript
Dynamsoft.DDV.formManager.setFieldProps(fieldUid, {
  value: true,
});
```

Hide a field:

```typescript
Dynamsoft.DDV.formManager.setFieldProps(fieldUid, {
  visible: false,
});
```

The properties you can update are defined in [`EditableFieldProps`]({{ site.api }}interface/editablefieldprops.html), including `value`, `readonly`, `required`, `visible`, `display`, `topIndex` and `isSignatureApplied`. When `isSignatureApplied` is set to `true`, the field and its associated signature controls are marked as signed.

## Locate the rendered form widgets in the viewer

### Get the widget DOM elements

Use [`getFieldElements()`]({{ site.api }}class/editviewer.html#getfieldelements) to get the widget DOM elements of a field that are already rendered in the current `EditViewer`. The result only contains the controls already rendered in the current viewer; the controls in virtual-rendered, invisible, or destroyed pages are not included.

```typescript
const elements = editViewer.getFieldElements(fieldUid);
elements.forEach(el => el.classList.add("is-active"));
```

### Navigate to a field

Use [`goToField()`]({{ site.api }}class/editviewer.html#gotofield) to navigate to the page containing the field and scroll the first rendered control of the field to the center of the viewport.

```typescript
const located = editViewer.goToField(fieldUid);
if (!located) {
  console.warn("The field does not exist or is not rendered yet.");
}
```

## Respond to widget clicks

Use the `widgetClicked` event of `EditViewer` to detect clicks on the rendered form widgets. The listener receives an [`IWidgetClickedEvent`]({{ site.api }}interface/iwidgetclickedevent.html) object which contains the field uid, the widget uid, the clicked DOM element and the [`WidgetStyle`]({{ site.api }}interface/widgetstyle.html) of the widget.

```typescript
const listener = (event) => {
  console.log("A widget is clicked", event.fieldUid, event.widgetUid);
  const field = Dynamsoft.DDV.formManager.getFieldRawByUid(event.fieldUid);
};

editViewer.on("widgetClicked", listener);

// Unbind the listener when it is no longer needed.
editViewer.off("widgetClicked", listener);
```

The `style` attribute describes the layout and display state of the widget (position, size, appearance state). It is not a `CSSStyleDeclaration`; to modify the widget style, use the DOM element `event.el` or the application-side style management.

## A complete example

The following example opens a document in an `EditViewer`, fills in the field "Name", checks the field "Agree", navigates to the field "Signature" and listens for widget clicks.

```typescript
// Assume that editViewer is an existing instance of EditViewer and a document is currently open.
const docUid = editViewer.currentDocument.uid;

// 1. Get the fields of the document.
const raws = Dynamsoft.DDV.formManager.getFieldRaws(docUid);
const fieldMap = new Map(raws.map(raw => [raw.uid, raw]));

// 2. Fill in the fields by their names.
fieldMap.forEach((field, fieldUid) => {
  if (field.name === "Name") {
    Dynamsoft.DDV.formManager.setFieldProps(fieldUid, { value: "John" });
  }
  if (field.name === "Agree") {
    Dynamsoft.DDV.formManager.setFieldProps(fieldUid, { value: true });
  }
});

// 3. Navigate to the field to sign.
const signatureField = [...fieldMap.values()].find(field => field.name === "Signature");
if (signatureField) {
  editViewer.goToField(signatureField.uid);
}

// 4. Listen for widget clicks.
editViewer.on("widgetClicked", event => {
  console.log("Field uid:", event.fieldUid);
  console.log("Widget style:", event.style);
});
```
